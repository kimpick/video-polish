# 시행착오 기록 (2026-10-13 첫 작업: VS Code+Claude 챗봇 → GitHub → Vercel 영상, 4분 41초)

## 내용·자막
1. **마우스 호버를 선택으로 읽지 말 것.** 질문 창에서 커서가 "Vercel 배포" 위를 지나가는 프레임을 보고 "Vercel을 선택해요"라고 썼다가 틀렸다(실제 흐름은 로컬 테스트 후 GitHub·Vercel을 따로 진행). 클릭 결과(라디오 체크, Submit 이후 화면)가 보이는 프레임만 근거로 쓴다. 안 보이면 "방향을 물어봐요"처럼 사실만 쓴다.
2. 사용자가 컷편집한 구간(오류 해결 과정)에는 자막을 넣지 않는다. 구간을 모르면 묻는다.
3. 줌된 구간은 화면이 확대되어 있어 위쪽 중앙 자막이 창 제목·팝업을 가린다. 판독 불가한 작은 글씨는 원본에서 crop해서 읽는다.
4. 영상에 API 키가 그대로 노출돼 있었다. 발견하면 시간대를 알리고 사용자가 결정(이번엔 이미 파기해서 그대로 둠).
5. 시트 마지막 타일이 검게 비는 것을 영상 오류로 오해할 뻔했다. tile 필터의 padding이다.

## TTS (Gemini)
1. **스타일 지시문을 텍스트에 붙이면 그것까지 읽는다.** "Read warmly ...: 문장" → 4초 문장이 15초가 됐다. 지시문 없이 보낸다. 톤은 목소리로 고른다.
2. **모든 클립에 잡음이 있다.** 맨 앞 10ms에 -1~0dB 틱, 맨 끝 0.2~0.3초에 0dB 버스트("치익"). 음성은 그 사이에서 -50dB 무음을 거쳐 끝난다. 사용자가 "10초쯤 치익", "시작할 때 틱"으로 두 번 짚었다. `trim-narr.ps1`이 해결한다.
3. **고정 길이로 끝을 자르면 안 된다.** 같은 문장을 다시 생성하면 끝 위치가 달라져서(음성이 끝까지 가는 경우) 고정 0.3초 컷은 말끝을 먹을 수 있다. 끝의 마지막 무음 구간을 찾아 그 안에서 자른다. 원본은 `narr_raw`에 보관하고 항상 거기서 다시 트림한다.
4. **429 (분당 한도)**: 큐 8개쯤 연속 호출하면 걸린다. 20초×시도횟수 대기 후 재시도한다.
5. 클립 번호는 큐 순서에 묶인다. 큐를 끼워 넣으면 `narr_raw` 파일을 뒤에서부터 한 칸씩 밀고 새 큐만 재생성한다.
6. 모델 ID는 바뀐다(2.5 preview → 3.1 preview → 3.8). 목록 조회로 고른다.
7. 영문·기호는 한글 발음 표기로 `say`에 적는다.

## 합성(ffmpeg)
1. `sidechaincompress`는 가장 짧은 입력에서 끝난다 → 낭독 트랙을 `apad=whole_dur`로 영상 길이까지 채우지 않으면 오디오가 낭독 마지막 지점에서 끊긴다(오디오 길이 2초 사고).
2. 낭독 후 BGM 덕킹은 sidechaincompress(threshold 0.03, ratio 8, attack 20, release 400).
3. 최종 믹스에 `alimiter=limit=0.95`. 없으면 0dB 클리핑.
4. BGM 음량: 곡마다 원음이 다르다(-11.7dB ~ -22.8dB). 평균 음량을 재서 -29dB 근처로 맞추는 공식 `vol = 10^((-29-mean)/20)`을 쓴다(수동으로 맞춘 값과 일치).
5. 짧은 루프는 `-stream_loop -1`로 반복. wav는 이음매가 매끄럽고, **mp3는 이음매마다 무음 틈(0.05초 이상)** 이 생긴다.
6. 한글 자막은 drawtext의 `textfile=`로 넣는다(필터 문자열 이스케이프 지옥 회피). 폰트 `malgunbd.ttf`.
7. `-ss`/`-to` 조합이 이 ffmpeg 빌드에서 거부됐다(원인은 아래 PS 인코딩 문제였으나), 자르기는 `atrim` 필터로 통일했다.
8. 이미지 시퀀스는 `%02d` 패턴. `-pattern_type glob`은 지원되지 않는다.

## PowerShell 5.1 함정 (스크립트가 이상하게 죽을 때)
- `$args`는 예약 변수다. 쓰지 않는다.
- 변수·파라미터 이름은 대소문자를 구분하지 않는다. `param([string]$Cues)`와 `$cues = ...`가 같은 변수라 배열이 문자열로 변환됐다.
- **BOM 없는 UTF-8 스크립트에서 한글 주석 줄의 줄바꿈이 사라져 다음 줄(변수 할당)이 주석에 먹힌다.** 스크립트는 UTF-8 BOM으로 저장한다(스킬의 .ps1은 BOM 적용 완료). 도구로 파일을 고친 뒤엔 BOM 재적용: `[IO.File]::WriteAllText($p,[IO.File]::ReadAllText($p,[Text.Encoding]::UTF8),(New-Object Text.UTF8Encoding($true)))`.
- `ConvertFrom-Json`은 JSON 배열을 **하나의 객체**로 내보낸다. `@(... | ConvertFrom-Json)`만 쓰면 한 겹 더 중첩돼 `$c.say`가 배열이 되고 API가 400을 낸다. `| ForEach-Object { $_ }`로 풀어서 받는다.
- 네이티브 명령(ffmpeg)의 stderr는 `$ErrorActionPreference = "Stop"`에서 오류로 처리된다. 호출부에서 일시적으로 `Continue`로 바꾸거나 `-v quiet`를 쓴다. 부모 스크립트의 Stop은 자식 스크립트에도 상속된다.
- `... | Select-Object -First 2`는 파이프라인을 끊어 **앞 단의 반복 작업을 중단**시킨다(트림이 2개만 처리됨). 출력 줄이기용으로 쓰지 않는다.
- bash의 `python`은 Windows 스토어 별칭이라 동작하지 않는다. PowerShell과 ffmpeg로 처리한다.
- `Remove-Item` 포함 명령은 자동 분류기가 막는 경우가 있다(명령 전체가 실행 안 됨). 삭제는 꼭 필요할 때만, 별도 호출로.
- 파일 편집 도구로 .ps1을 고치면 BOM이 빠질 수 있다.

## 작업 방식
- 소리는 직접 들을 수 없다. 구간별(0.5초) `volumedetect`로 낭독 단독/BGM 단독/최종 믹스를 분리 측정해 원인을 찾는다. 결과 보고에 "직접 듣지 못했다"를 적는다.
- 영상 파일을 받았을 때 경로의 다른 mp4(강의 녹화)와 혼동하지 않는다.
- 사용자 피드백은 구간 단위로 온다("10초쯤 치익"). 해당 시각의 믹스 구성요소를 분리해서 확인하고 같은 부류의 문제를 전체 클립에서 한 번에 점검한다(12개 모두 같은 증상이었다).
